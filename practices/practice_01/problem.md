# Проблема и метрики

## Проблема

- Пользователь: Клиент сервиса, который хочет получить автоматическое ревью PR по предоставленному диффу.
- Ситуация: Клиент отправляет POST `/api/reviews` с JSON телом, ожидая стабильный ответ с результатом ревью.
- Что происходит сейчас: Вход не валидируется, при отсутствии ключа `diff` возникает исключение (`KeyError`) и 500; ошибки и таймауты LLM не обрабатываются; маршрут синхронный и может блокироваться долгим вызовом.
- Почему это мешает пользователю или бизнесу: Непредсказуемые 5xx ухудшают надёжность API, повышают время простоя и стоимость поддержки; долгие блокировки снижают пропускную способность; отсутствует договорённость по структуре ответа.
- Что не входит в задачу: Переписывание кода в `app/` в рамках этой практики; проектирование полноценной схемы аутентификации и биллинга.

## Метрики

Выберите измеримые показатели, относящиеся к проблеме. Не используйте VTG, IRR, WACC, CSAT или другую метрику только ради названия.

| Метрика | Текущее значение или способ замера | Целевое изменение | Когда измеряем | Источник данных |
|---|---:|---:|---|---|
| Доля запросов, завершающихся 5xx на POST /api/reviews | Сымитировать N запросов с отсутствующим ключом `diff` и с ошибкой LLM | → 0% для отсутствующего ключа; контролируемые 4xx/5xx для LLM | После ввода валидации/обработки ошибок | Логи/метрики FastAPI |
| Среднее время ответа P50/P95 для POST /api/reviews | Замерить на выборке из M запросов разного размера `diff` | Не ухудшать P50; P95 ≤ заданного SLA | После оптимизаций/ограничений размера | APM/метрики |
| Доля корректно распознанных входов | Количество запросов с валидным/невалидным телом | 100% корректная классификация с соответствующим статусом | После добавления схемы запроса | Валидационные логи |
Снижение 5xx при некорректном входе показывает, что валидация работает и ошибки переводятся в предсказуемые 4xx. Контроль времени ответа на P95 подтверждает, что длинные диффы и вызовы LLM не приводят к деградации производительности. Рост доли корректно обработанных входов подтверждает, что контракт API ясен и соблюдается.
