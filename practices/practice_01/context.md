## Context Pack для первого рабочего сценария

### Факты и правила

Правила репозитория, применимые к сценарию `POST /api/reviews` (формулировка приводится при первом употреблении, далее — только ID):

- **SEC-1** — перед отправкой во внешний LLM из диффа удаляются токены, пароли, приватные ключи. Сейчас нарушено: `prompt = f"Review this pull request and find problems:\n{diff}"` подставляет дифф дословно.
- **API-1** — дифф длиннее 20 000 символов отклоняется с HTTP 413. Сейчас не соблюдается: вывод об отсутствии — в обоих хунках нет ни одной строки, проверяющей длину диффа.
- **REL-1** — LLM-вызов имеет timeout 10 секунд; ошибка превращается в контролируемый ответ. Сейчас нарушено: `answer = self.llm.generate(prompt)` вызывается без таймаута и без `try/except`.
- **OUT-1** — ответ содержит `summary`, массив `risks` и массив `checks`; в `risks` максимум три элемента с полями `file`, `line`, `evidence`, `risk`. Сейчас нарушено: `return {"comment": answer}` — одна строка вместо трёх полей.
- **SCOPE-1** — сервис только советует: не пишет код и не действует в GitHub, решение по PR принимает человек.
- **QA-1** — утверждение включается, только если подтверждено строкой диффа или правилом.
- **OBS-1** — в лог пишутся только `request_id`, длительность и статус; дифф и ответ модели не логируются. Соблюдение нечем подтвердить: вывод об отсутствии — в обоих хунках нет ни одной строки логирования.

Факты о коде, на которые опираются остальные артефакты:

- обработчик синхронный: `def create_review(payload: dict) -> dict[str, str]` (хунк `app/api.py @@ -1,8 +1,17 @@`);
- обращение к телу запроса идёт по ключу без проверки: `return review_service.review(payload["diff"])` (там же);
- в приложении уже есть `@app.get("/health")`, возвращающий `{"status": "ok"}` (там же);
- переоформление сигнатуры `def generate(self, prompt: str) -> str` с однострочной записи на многострочную поведение не меняет и риском не является (хунк `app/review_service.py @@ -1,10 +1,23 @@`).

### Формат входа и результата

- Вход: `POST /api/reviews`, `Content-Type: application/json`, тело `{"diff": "<unified diff>"}`.
- Результат сейчас (факт из хунка `app/review_service.py @@ -1,10 +1,23 @@`): `{"comment": "<строка ответа LLM>"}`.
- Результат целевой (по OUT-1): `{"summary": "...", "risks": [...], "checks": [...]}`, где `risks` — не более трёх элементов с полями `file`, `line`, `evidence`, `risk`.

### Ограничения и запрещённые действия

- Не отправлять во внешний LLM дифф с токенами, паролями и приватными ключами (SEC-1).
- Не принимать дифф длиннее 20 000 символов — такой запрос отклоняется с HTTP 413 (API-1).
- Не оставлять LLM-вызов без таймаута 10 секунд и без преобразования ошибки в контролируемый ответ (REL-1).
- Не возвращать клиенту свободный текст вместо `summary`/`risks`/`checks` (OUT-1).
- Не писать код в репозиторий пользователя, не действовать в GitHub, не approve и не merge PR (SCOPE-1).
- Не писать в лог дифф и ответ модели — только `request_id`, длительность и статус (OBS-1).
- Не включать в артефакты утверждения без цитаты из хунка или ID правила (QA-1).

### Хороший пример

Запрос: `POST /api/reviews` с телом `{"diff": "diff --git a/app/api.py ..."}` длиной 4 000 символов, без секретов.

Ответ по OUT-1:

```json
{
  "summary": "Обработчик создания ревью не проверяет тело запроса и вызывает LLM без таймаута.",
  "risks": [
    {"file": "app/api.py", "line": "@@ -1,8 +1,17 @@", "evidence": "return review_service.review(payload[\"diff\"])", "risk": "Тело без ключа diff приводит к KeyError"},
    {"file": "app/review_service.py", "line": "@@ -1,10 +1,23 @@", "evidence": "answer = self.llm.generate(prompt)", "risk": "Вызов LLM без таймаута и обработки ошибки, нарушение REL-1"},
    {"file": "app/review_service.py", "line": "@@ -1,10 +1,23 @@", "evidence": "prompt = f\"Review this pull request and find problems:\\n{diff}\"", "risk": "Дифф подставляется дословно, нарушение SEC-1"}
  ],
  "checks": [
    "Тело {} → 422 и ноль вызовов заглушки LLM",
    "Дифф длиной 20 001 символ → 413 и ноль вызовов заглушки LLM",
    "Заглушка LLM не отвечает 11 секунд → контролируемый ответ, а не необработанная ошибка"
  ]
}
```

Пример хороший, потому что в каждом элементе `risks` поле `evidence` — дословная строка из хунка, ссылка на код дана заголовком хунка, элементов ровно три (OUT-1), а каждая проверка названа как конкретный вход и наблюдаемый критерий.

### Плохой пример

Ответ `{"comment": "В коде есть проблемы с безопасностью и производительностью, рекомендуется добавить тесты и улучшить архитектуру. Проблема в app/api.py, строки 35–38."}`.

Пример плохой по трём причинам: форма `{"comment": "<строка>"}` не содержит `summary`, `risks`, `checks` (нарушение OUT-1); «добавить тесты» — намерение, а не проверка с наблюдаемым критерием; ссылка «строки 35–38» невоспроизводима — оба файла в диффе начинаются со строки 1, ссылаться следует заголовком хунка `app/api.py @@ -1,8 +1,17 @@` (QA-1).

### Что пока неизвестно

- Целевой профиль трафика (RPS, число одновременных клиентов, длительность прогона): в хунках и правилах его нет, поэтому любые числа нагрузки в [`tests_load.md`](tests_load.md) помечены как допущение прогона.
- Коды ответа для пустого тела, ошибки LLM и таймаута: правилами задан только 413 (API-1), остальные коды — проектное решение, зафиксированное в [`adr.md`](adr.md).
- Реализация маскирования по SEC-1 (перечень шаблонов секретов): в хунках нет ни одной строки маскирования, требование известно только по ID.

Закрытые решения по ранее открытым вопросам:

- Способ измерения длины диффа: порог API-1 применяется к числу символов декодированной строки `diff` после разбора тела. Единица измерения — проектное решение этой работы, правилами не задана (API-1 задаёт порог 20 000 символов и код 413, но не способ подсчёта); решение пересматривается при появлении правила о способе подсчёта.

## Как использовали AI

- Для чего: собрать контекст AS IS и Context Pack по одному сценарию `POST /api/reviews` из хунков `TRAINING_PR.diff` и правил SEC-1, API-1, REL-1, OUT-1, SCOPE-1, QA-1, OBS-1.
- Тип промпта: master prompt (структурированная инструкция с ролью, источниками, запретами и Definition of Done).
- Строка в [`prompts.md`](prompts.md): P1-03.
- Что проверил студент и какие исправления поручил агенту: сверил каждую ячейку таблицы с текстом хунков — цитаты `payload["diff"]`, `answer = self.llm.generate(prompt)`, `return {"comment": answer}` совпадают дословно. Поручил убрать ссылки на выдуманные номера строк и заменить их заголовками хунков, так как оба файла в диффе начинаются со строки 1. Поручил перенести неизвестный профиль трафика в раздел «Что пока неизвестно», а не подставлять правдоподобные RPS. Отдельно проверил, что переоформление сигнатуры `def generate` записано как изменение без влияния на поведение, а не как риск.
