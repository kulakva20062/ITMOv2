# Макет AutoDrive v2 — основной сценарий (практика 8, редизайн B)

Откройте `index.html` двойным кликом — это **статический кликабельный макет редизайна**
`Vanilla JS + Bootstrap` → `React + Vite + TypeScript + Tailwind CSS + shadcn/ui` по
[`../project/docs/design-contract.md`](../project/docs/design-contract.md) (v2.1.0). Вкладки
переключаются на чистом CSS (`radio` + `:checked`): **ни JS, ни сборки, ни внешних ресурсов** —
файл работает офлайн и открывает консоль без ошибок.

Это не рабочее приложение, а эталон вида и состояний для миссий M4–M8. Библиотека компонентов,
которую повторяет макет, — **shadcn/ui** (виды `Button`, `Input`, `Select`, `Checkbox`, `Label`,
`Card`, `Badge`, `Separator`, `Spinner` аппроксимированы собственными CSS-классами из токенов
контракта).

## Экраны

Сценарий «выбрать машину → рассчитать → отправить заявку → увидеть номер» разложен на
9 экранов + вкладку движения:

1. **Лендинг** — тёмная сцена целиком: `SiteHeader` + `HeroSection` (blueprint-сетка, SVG-развёртка
   в финальном кадре, CTA `href="#fleet"`) + `SiteFooter` с `#contacts`; ниже paper-секции
   `#benefits / #how / #faq`. Один `h1` на странице (§5.1–5.2, §5.6).
2. **Автопарк** `#fleet` — карточки машин с полями «Класс / Коробка / Салон / Цена за сутки»,
   фильтр-селекты, `#fleet-count` («Показано N из M»), выбранная карточка `data-chosen`
   (тёмная граница + жёлтая обводка) и `#fleet-status`; ниже — состояние пустого результата (§5.3).
3. **Расчёт** `#calculator` — форма срока и опций + общий чек `Receipt` со всеми строками: база,
   скидка, опции, полная страховка, итог, залог (§5.4, §4.1.1).
4. **Заявка — нет расчёта** `data-state=no-estimate` — пустая панель со ссылкой на калькулятор;
   поля и кнопка **реально `disabled`** (§6.1).
5. **Заполнение** `data-state=editing` + кадр **360px** — снимок расчёта, три подписанных поля,
   **двойной индикатор фокуса** на имени, одноколоночная раскладка без скролла (§5.5, §6.1, §9).
6. **Ошибки ввода** — `aria-invalid` + `role="alert"` под каждым полем, тексты из каталога (§7).
7. **Отправка** `data-state=submitting` — спиннер в кнопке, `aria-busy`, блокировка полей (§6.1, §8).
8. **Успех** `data-state=success` — штамп в финальном кадре `rotate(-3deg)`, чек подтверждения,
   кнопка «Оформить ещё одну заявку» (§3.3, §5.5).
9. **Ошибка сервера** — `unavailable` (5xx/таймаут) и частный случай 409 `date_conflict` (§6.2).
10. **Движение** — статичные кадры пяти паттернов из §3: `stroke-draw` (t=0 → середина → финал),
    `reveal`, `stamp`, `shake`, `hover-glow` с подписями таймингов и motion-бюджетом §3.6.

## Откуда числа и строки

Никаких выдуманных значений — всё пересчитано из чистых модулей проекта:

- автопарк, цены, «Салон» — [`../project/src/cars.js`](../project/src/cars.js) (`seatsLabel`);
- суммы чека — [`../project/src/calc.js`](../project/src/calc.js) (`calculateRental`), формат —
  [`../project/src/format.js`](../project/src/format.js) (`formatPrice`/`formatDate`).
  Сквозной пример: **Корда Мини, 7 суток, «Второй водитель» + «Полная страховка»** →
  база 20 300 ₽, скидка 10 % −2 030 ₽, опции 3 500 ₽, страховка 2 741 ₽,
  **итог 24 511 ₽**, залог 10 000 ₽;
- тексты заявки и ошибок — [`../project/src/booking-text.js`](../project/src/booking-text.js)
  (`BOOKING_TEXT`, `errorView`), сообщения фильтра — `src/filter.js` (`EMPTY_MESSAGE`, `countLabel`).

В скопированных строках в подписях экранов указан файл-источник.

## Визуал

Токены §2 контракта вынесены в CSS-переменные `:root` (paper) и `.surface-night` (тёмная
поверхность шапки/hero/footer), поверх них — shadcn-отображение (`--background`, `--foreground`,
`--primary`, `--input`, `--ring`, `--destructive`…). Финальные кадры анимаций (reveal,
stroke-draw, штамп) — **базовые стили**, а не `@keyframes`: поэтому вид совпадает с тем, что
получают скриншотные тесты M6 при `prefers-reduced-motion: reduce`. Тени есть только как
`--glow-signal` в hover; градиент — только blueprint-сетка hero.

## Сверка с приложением

Макет сверен с React-приложением на `/`. В автопарке восемь машин в том же порядке,
выбрана Корда Мини. В калькуляторе, снимке заявки и подтверждении использованы одни
входные данные — 7 суток, второй водитель и полная страховка. Итог во всех трёх
кадрах — 24 511 ₽. Дата поездки и номер заявки на живых кадрах получаются при запуске.
[Скриншоты приложения](../project/docs/screenshots) · [Отчёт](../REPORT.md)

Селекторы и тексты §5 повторяются в разметке. У полей в разных состояниях есть
префиксы (`empty-`, `err-`, …), чтобы id оставались уникальными. Канонические
селекторы указаны в подписях к экранам.

## Как макет создавался с AI (v2)

Инструмент: agentic-сессия (Claude / OpenCode) — перестройка v1-макета по design-contract v2.
Формат ниже: **что предложил AI → что изменено после проверки студентом.**

Промпт первой итерации:

> Перестрой `mockup/index.html` с v1 (Bootstrap) на вид v2 по `docs/design-contract.md` v2.1.0.
> Токены §2 вынеси в CSS-переменные (`:root` = paper, `.surface-night` = тёмная). Тёмные шапка,
> hero и footer; paper-секции. Добавь вкладку «Движение» со статичными кадрами §3. Состояния
> заявки — по §6. Числа — из `src/cars.js`/`src/calc.js`, строки — из `src/booking-text.js`. Без
> сборки и внешних ресурсов: файл открывается двойным кликом.

Итерации и правки:

- **Стек отображения.** AI предложил оставить подключённый Bootstrap и/или тянуть Tailwind+React
  через CDN со сборкой → изменено: **Bootstrap удалён**, внешний вид — собственная статическая
  CSS-аппроксимация shadcn-видов из токенов, никаких внешних ресурсов и JS-сборок (§0/§10).
- **Вкладки.** AI сделал переключение на JS-обработчиках клика → изменено: вкладки на CSS
  (`radio` + `:checked`), чтобы не было ни одного `<script>` и риска ошибок консоли.
- **Фокус.** AI поставил одиночную жёлтую обводку `--signal` на всех поверхностях (как в v1) →
  изменено: на paper **двойной** индикатор (`outline --ink` + жёлтое кольцо), на night — одиночный
  `--signal` (§2.3, §9); продемонстрирован на имени в editing и на CTA hero.
- **Состояние «нет расчёта».** AI оставил поля лишь визуально серыми (наследный баг v1) →
  изменено: у всех трёх полей и кнопки реально стоит атрибут `disabled` (недоступны и для Tab).
- **Финальные кадры анимаций.** AI заложил живые `@keyframes`/JS reveal → изменено: reveal,
  stroke-draw и штамп зафиксированы как **статичные базовые стили финального кадра**; движение
  показано отдельными кадрами на вкладке «Движение». Это снимает недетерминизм скриншотов.
- **Числа.** AI перенёс разрозненные суммы v1 (то 21 770, то 18 270) → изменено: один сквозной
  расчёт из `calculateRental` (24 511 ₽), согласованный между калькулятором, снимком и
  подтверждением; добавлены строки «Опции» и «Полная страховка», которых в v1 не было.
- **Подписи полей.** AI сохранил звёздочки `Имя *` из v1 → изменено: `BOOKING_TEXT.labels`
  («Имя / Телефон / Дата начала аренды»), звёздочка — только в `#booking-required`.
- **`.fleet__head`.** AI оставил шапку таблицы реестра → изменено: не рендерится, карточная
  раскладка (§10); добавлен жетон `Выбрана` и `#fleet-status`.
- **Вкладка «Движение».** AI показал hero-развёртку одним итоговым кадром → изменено: три кадра
  `stroke-draw` (t=0 / ≈600 мс / финал ≤2500 мс) плюс кадры reveal, stamp, дорожка shake и
  hover-glow с подписями таймингов §3 и motion-бюджетом §3.6.
- **Отметка выбора.** AI ограничился жёлтой обводкой выбранной карточки → изменено: по §2.3
  `border --ink` + `outline 2px --signal` и дублирование текстом в `#fleet-status`.

## Сознательные упрощения макета

- Экран 9 совмещает два сбоя (5xx/таймаут и 409), экран 5 — editing и 360px-раскладку.
- Кадр 360px — статичная имитация узкой раскладки, а не реальный рендер во вьюпорте 360.
- Якоря навигации/CTA ведут на существующие `id` макета (для соответствия §5.1–5.2), но переключение
  вкладок — по клику на саму вкладку, не по клику-скроллу по секции.
