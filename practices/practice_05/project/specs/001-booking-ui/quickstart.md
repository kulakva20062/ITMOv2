# Phase 1 — Quickstart: как проверить UI заявки

Руководство по проверке, не по реализации. Коды и тексты — в
[`specs/contracts/booking-contract.md`](../../contracts/booking-contract.md) §7, интерфейс модулей —
в [`contracts/ui-modules.md`](./contracts/ui-modules.md).

## Предварительные условия

- Node 24, зависимостей ставить не нужно.
- Порт 8000 свободен.
- Хранилище заявок — в памяти процесса: **перезапуск сервера обнуляет брони и нумерацию с `AD-0001`**.
  Это рычаг для повторяемых проверок конфликта дат.

## 1. Раннер проекта

```sh
sh scripts/check.sh
```

Должен быть зелёным после каждой правки (принцип III). Новое покрытие:

| Файл | Что доказывает |
|---|---|
| `tests/booking-text.test.js` | каждая из 17 строк каталога §7 отдаёт ровно свой текст; обе ветки `name_length`; подстановка `BOOKING_HORIZON_DAYS`; нераспознанный код даёт «Заявка не принята…» |
| `tests/booking-form.test.js` | `responseView` на всех исходах; приоритет «расчёт устарел» над ошибками полей; `conflictText` на контрольном примере и на битом `conflict`; `bookingPayload` не содержит сумм; `200` и `201` дают одинаковый успех |
| `tests/booking-markup.test.js` | секция между `#calculator` и `#benefits`; ссылка в меню; `label for` у трёх полей; `role="alert"` у трёх областей ошибок; `role="status"` у области состояния; `aria-describedby` ведёт на существующие `id` |

Проверка, что ничего не сломано: тесты фич A, B и C должны остаться зелёными без правок
(разбор рисков — research R-09).

## 2. Страница

```sh
npm start        # node server.js, http://localhost:8000/
```

Страница и `/api` — один источник, CORS не участвует.

## 3. Сценарии в браузере (MCP playwright, 360 и 1280 px)

Каждый сценарий прогоняется на **обеих** ширинах: `browser_resize` 360×800 и 1280×900. На каждой
ширине проверяется отсутствие горизонтальной прокрутки:
`document.documentElement.scrollWidth <= window.innerWidth`.

| № | Сценарий | Ожидаемый результат |
|---|---|---|
| 1 | Открыть страницу, прокрутить к `#booking`, ничего не считая | `data-state="no-estimate"`, поля и кнопка недоступны, видна ссылка на калькулятор |
| 2 | Рассчитать аренду в калькуляторе | `data-state="editing"`, снимок повторяет машину, срок, опции и итог расчёта |
| 3 | Отправить пустую форму | три ошибки сразу, у каждого поля `aria-invalid="true"`, фокус на поле имени, запрос не ушёл |
| 4 | Исправить только имя | ошибка имени и её `aria-invalid` снялись, ошибки телефона и даты на месте |
| 5 | Имя `Иван123` | текст строки `name_charset` |
| 6 | Телефон `123` | текст про 11 цифр с образцом `+7 000 000-00-00` |
| 7 | Дата на +400 суток | текст с числом **365**, взятым из `BOOKING_HORIZON_DAYS` |
| 8 | Корректная заявка | `data-state="success"`, номер `AD-0001`, модель, дата `ДД.ММ.ГГГГ`, срок и итог; **телефона в подтверждении нет** |
| 9 | «Оформить ещё одну заявку» | `data-state="no-estimate"`, поля пусты, итог калькулятора сброшен |
| 10 | Та же машина и пересекающиеся даты второй заявкой | ошибка у поля даты с **последним занятым днём**: для `[10.11, 13.11)` текст «с 10.11.2026 по 12.11.2026» |
| 11 | Та же машина, дата начала = день возврата предыдущей брони | заявка проходит: встык разрешён (§8) |
| 12 | Повторить заявку, полностью совпадающую с принятой | успех с **тем же** номером, вторая бронь не создаётся (§9) |
| 13 | Рассчитать, начать заполнять, затем изменить срок в калькуляторе | `data-state="no-estimate"`, имя, телефон и дата сохранены |
| 14 | Остановить сервер и отправить заявку | `data-state="unavailable"`, текст «Заявка не отправлена — сервер не ответил…», всё введённое на месте |
| 15 | Поднять сервер и нажать кнопку снова | успех; если первая заявка всё же создалась, номер тот же (§9) |
| 16 | Пройти форму только клавиатурой: Tab до полей, ввод, Enter | порядок обхода — имя, телефон, дата, кнопка; фокус виден; недоступные элементы пропускаются |

Сценарий 10 удобно готовить так: перезапустить сервер (чистое хранилище), оформить заявку на
известные даты, затем пытаться забронировать ту же машину внутри этого интервала.

### Что смотреть на 360 px отдельно

- Одна колонка: снимок над полями, подписи над полями, кнопка по ширине колонки.
- Высота касания полей, кнопки и ссылки на калькулятор — не меньше 44 px.
- Длинное имя (60 символов) и номер вида `AD-10000` не выходят за границы секции.

### Что смотреть на 1280 px отдельно

- Поля не растянуты на всю страницу; рейка с подписью секции слева, как в соседних секциях.
- Снимок и поля читаются как один лист: без карточек, теней и градиентов.

## 4. Проверка стиля и контраста

- Новых цветов нет: только `--paper`, `--ink`, `--ink-2`, `--rule`, `--signal`, `--stamp`;
  `--stamp` — исключительно текст и подчёркивание ошибки ввода.
- Контраст пар с `--paper` уже закреплён тестом `tests/contrast-mcp.test.js`; новых пар
  не вводится, поэтому отдельная проверка не нужна — достаточно не добавлять цветов.
- Новой анимации нет; `prefers-reduced-motion` ничего нового уважать не должен.
- Общий аудит вёрстки: скилл `landing-check`.

## 5. Признаки, что фича не готова

- `sh scripts/check.sh` красный.
- В `src/main.js` появилось условие про код ошибки, состояние или формулировку — значит решение
  утекло из чистых функций в связку (принцип II).
- В разметке или `styles.css` появилась строка текста, которой нет в `src/booking-text.js`.
- Посетитель увидел `error.message` из ответа сервера (SC-011).
- Телефон появился в подтверждении (§5, §12 — вне объёма).
