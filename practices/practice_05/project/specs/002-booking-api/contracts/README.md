# Contracts — booking-api

Два уровня контрактов, и путать их нельзя.

## Внешний контракт (источник имён) — не в этой папке

[`specs/contracts/booking-contract.md`](../../contracts/booking-contract.md) v1.0.0 —
согласованный двумя командами и владельцем документ. Это **единственный источник** имён
полей, кодов ошибок, состояний UI, текстов, путей, кодов HTTP и формы тел запроса и ответа
(принцип V конституции).

Здесь он **не дублируется и не пересказывается**. Если нужно знать, как называется поле или
какой код отдавать — смотреть туда:

| Вопрос | Раздел |
|---|---|
| поля запроса, типы, лимит 8 КБ | §4 |
| тела `201` / `200` / ошибок, таблица кодов ответов, ручки v1 | §5 |
| правило телефона | §6 |
| каталог «код → поле → состояние UI → текст» | §7 |
| интервал и пересечение | §8 |
| повторная отправка | §9 |

## Внутренние контракты модулей — [`internal-modules.md`](./internal-modules.md)

Сигнатуры и формы возврата функций `src/booking.js`, `src/booking-store.js`, `server.js` и
дополнения `src/format.js`. Контракт §3 называет эти функции по именам, но не описывает,
что они принимают и возвращают — этот пробел и закрывает `internal-modules.md`.

Это **внутренний** контракт: он не вводит ни одного нового имени поля, кода ошибки или
видимого текста. Если внутренняя сигнатура когда-нибудь потребует нового имени в теле
запроса или ответа — это признак, что нужна правка внешнего контракта, а не этого файла.
