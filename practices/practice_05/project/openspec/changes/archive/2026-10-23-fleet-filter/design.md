# Design

## Context

Мотивация — в `proposal.md` (раздел Why), требования — в `specs/fleet-filtering/spec.md`.

Устройство, в которое встраивается фильтр, уже готово к нему наполовину:

```
src/cars.js                   src/render.js                   src/main.js
+------------------------+    +----------------------+        +--------------------------+
| CAR_CLASSES  [4]       |    | fleetHtml(list)      |<-------| list.innerHTML =         |
| GEARBOXES    [2]       |--->|  list.map(carRowHtml)|        |   fleetHtml(cars)        |
| CLASS_LABELS {ru}      |    |  * чистая, без DOM   |        |   * вызов один раз       |
| GEARBOX_LABELS {ru}    |    +----------------------+        +--------------------------+
| cars [8]               |
+------------------------+
```

Что из этого следует для подхода:

- `fleetHtml(list)` уже принимает произвольный список — ей безразлично, полный он или отобранный. Перерисовка отобранного списка не требует правок `render.js`.
- Русские подписи классов и коробок (`CLASS_LABELS`, `GEARBOX_LABELS`) уже экспортированы: опции селектов строятся из них, новых данных не нужно.
- В `#fleet` уже есть `#fleet-status` с `role="status"`, занятый сообщением о выбранной машине, и шапка `.fleet__head` — отдельный грид на 6 колонок с `aria-hidden="true"`, живущий **вне** контейнера `#fleet-list`.
- Сама `.fleet` гридом не является: у неё только ширина, отрицательный левый отступ и верхняя линия. Грид задан правилом `.fleet__head, .car`. Блок фильтра поэтому встаёт соседом `div.fleet` (как уже стоит `#fleet-status`), а не его ребёнком, и во внутреннюю сетку реестра не попадает.
- Распределение машин: economy 2, comfort 2, business 2, suv 2; manual 3, automatic 5. Не все пары класс×коробка заполнены — `business + manual` пусто. Пустой результат достижим обычным выбором, а не только крайним случаем.

Ограничения проекта: без фреймворков и сборщиков, логика расчётов — чистыми функциями в `src/` под тестами (`AGENTS.md`), токены и правила вёрстки — `docs/style-guide.md`, единственный runner — `sh scripts/check.sh`.

## Goals / Non-Goals

**Goals:**

- Логика отбора — чистая функция без DOM, проверяемая напрямую тестами.
- Встроиться в существующий поток «данные → `fleetHtml` → `innerHTML`», не вводя второй способ рисовать автопарк.
- Не ослаблять и не править существующие тесты фич A и B.

**Non-Goals:**

- Реактивность и наблюдаемое состояние: смена фильтра перерисовывает список целиком, это восемь строк.
- Сохранение состояния фильтра между загрузками страницы.
- Вынос фильтра в переиспользуемый компонент: он нужен ровно в одном месте.

## Decisions

### Отбор чистой функцией и перерисовка, а не скрытие строк через CSS

`filterCars(cars, { carClass, gearbox })` в новом `src/filter.js` возвращает новый массив, `main.js` зовёт `fleetHtml(filtered)` и присваивает `innerHTML`.

Альтернатива — проставить карточкам `data-car-class` / `data-car-gearbox` и скрывать строки атрибутом `hidden` или CSS-селектором по контейнеру. Отвергнута: логика отбора уехала бы в DOM-слой, где её не покрыть тестами напрямую, а `AGENTS.md` требует держать логику чистыми функциями в `src/`. Перерисовка восьми строк стоит дешевле, чем потеря тестируемости. Кроме того, при скрытии через CSS счётчик «Показано N из M» всё равно пришлось бы считать в JS — то есть логика дублировалась бы в двух местах.

Отдельный файл `src/filter.js`, а не дополнение к `src/cars.js`: `cars.js` — это данные и их словари, и он остаётся без изменений.

### Фильтр на двух `<select>`, а не на радиокнопках или чекбоксах

Это решение диктуется существующими тестами, а не вкусом. `tests/index.test.js:104` и `:126` ищут поле срока калькулятора нежадной регуляркой по всему документу:

```js
html.match(/<input[\s\S]*?id="calc-days"[\s\S]*?\/>/)      // старт — ПЕРВЫЙ <input> в файле
const describedBy = field.match(/aria-describedby="([^"]+)"/)?.[1]   // первое совпадение в блобе
```

`#fleet` стоит выше `#calculator`, поэтому любой `<input>` фильтра попал бы в начало этого блоба, и `aria-describedby` подхватился бы от фильтра вместо поля срока — тест фичи B упал бы. Правка этих тестов запрещена (`AGENTS.md`: не менять существующие тесты ради зелёного результата). `<select>` в регулярку не попадает.

Побочная выгода: `<select>` совпадает с `.field__control` калькулятора, поэтому оформление продолжает язык листа осмотра без новых CSS-приёмов и новых цветов.

### Значение «любой» кодируется строкой `'any'`

Селекты отдают строки, и `<option value="">` с пустой строкой читается в коде неотличимо от «значение не передали». Явная `'any'` делает отбор однозначным: `'any'` и `undefined` означают «без ограничения», любое другое значение вне `CAR_CLASSES` / `GEARBOXES` — `RangeError`. Так неизвестное значение нельзя случайно принять за «любой» и тихо показать весь автопарк.

Текст ошибки повторяет тон `calc.js` (`Нет такой машины в автопарке: … Выберите машину из списка.`): называем полученное значение и говорим, что исправить.

### Счётчик — своя живая область, рядом с селектами

Новый элемент с `role="status"` отдельно от `#fleet-status`. Если писать и счётчик, и «Выбрана Прима Седан» в одну область, сообщения затирают друг друга, и скринридер читает только последнее — две независимые фичи конкурировали бы за один канал. Разделение оставляет `#fleet-status` ровно тем, чем он был для фичи A.

### Пустой результат: сообщение в `#fleet-list`, шапка скрывается атрибутом `hidden`

Сообщение о пустом результате пишется в `#fleet-list` тем же присваиванием `innerHTML`, что и строки машин: один путь вывода, одно место, где может оказаться контент. Отдельный контейнер под сообщение в `index.html` не нужен.

`.fleet__head` лежит вне `#fleet-list`, поэтому перерисовка списка её не трогает — видимость переключается явно через `fleetHead.hidden`, возврат через `hidden = false`. Атрибут `hidden` предпочтён классу-модификатору: он несёт смысл «элемента сейчас нет» и для скринридера тоже.

Одного атрибута, однако, недостаточно: правило `.fleet__head, .car { display: grid }` — авторский стиль, и он перебивает UA-стиль `[hidden] { display: none }`. Поэтому в `styles.css` добавляется `.fleet__head[hidden] { display: none; }`. Его специфичность (0,2,0) выше и базового правила, и правила `.fleet__head { display: none }` в медиазапросе `max-width: 60rem` (оба 0,1,0), поэтому скрытие работает независимо от порядка правил, а медиазапрос продолжает работать как раньше. Побочное следствие: ниже 60rem шапка скрыта медиазапросом всегда, так что там переключение `hidden` визуально ничего не меняет — сообщение о пустом результате при этом показывается нормально.

### Восстановление `data-chosen` после перерисовки

`markChosen` вешает атрибут на DOM-узел, а `list.innerHTML = …` его сносит. Поэтому `main.js` хранит id выбранной машины в переменной модуля и после каждой перерисовки заново вызывает `markChosen`. Альтернатива — читать выбранное из `carField.value` — отвергнута: значение селекта калькулятора не равно «посетитель отметил эту машину в реестре», оно непусто с самой загрузки страницы (там стоит первая машина), и отметка появилась бы на строке, которую никто не выбирал.

Выбор меняется из двух мест, и переменная обновляется в обоих: клик «Рассчитать» в карточке и событие `change` селекта калькулятора (второй обработчик уже есть и сейчас зовёт `markChosen` напрямую). Если обновлять переменную только в одном из них, после смены фильтра отметка вернётся на устаревшую машину.

Когда выбранная машина отфильтрована, `markChosen` просто не находит строку — отметки нет, и это правильное состояние: выбор не отменён, он не виден. Поэтому `#fleet-status` при фильтрации не трогается, а машина остаётся выбранной в калькуляторе; при возврате фильтра отметка появляется снова из той же переменной.

### Разметка опций, текст счётчика и сообщение — тоже чистые функции в `src/filter.js`

`filterOptionsHtml`, `countLabel` и константа `EMPTY_MESSAGE` живут рядом с `filterCars`, а не в `render.js`. Причина — `render.js` остаётся без изменений: он уже покрыт тестами фич A и B, и каждая правка там создаёт риск для зелёного состояния, которого можно не брать. Всё, что фильтр добавляет, собрано в одном новом файле, и `tests/filter.test.js` покрывает это так же, как сам отбор.

Побочная выгода: текст счётчика и текст пустого результата становятся проверяемыми строками, а не строковыми литералами внутри DOM-обработчика, который тестами проекта не достаётся. Спека задаёт их дословно, тест сверяет дословно.

`filterOptionsHtml` прогоняет подписи через `escapeHtml` из `render.js` — импорт не меняет сам `render.js`. Подписи сейчас свои и безопасные, но экранирование здесь — дисциплина, принятая в `carRowHtml`, и отступать от неё в новом коде незачем.

## Risks / Trade-offs

- **Перерисовка `innerHTML` сбрасывает состояние DOM внутри `#fleet-list`** (фокус, отметка выбранной машины) → `data-chosen` восстанавливается явно; фокус внутри списка в момент смены фильтра не находится, потому что фокус в этот момент на селекте фильтра, который лежит вне списка.
- **Регулярки в `tests/index.test.js` хрупкие и могут выстрелить снова** при следующих правках `#fleet` → зафиксировано решением «только `<select>`» выше и проверяется прогоном `sh scripts/check.sh` после правки разметки; ослаблять тесты нельзя.
- **Новые селекты на ширине 360 px могут дать горизонтальный скролл** → критерий приёмки A (нет горизонтального скролла на 360 px и 1280 px) остаётся в силе, проверяется в браузере перед приёмкой; блок фильтра стоит соседом `div.fleet`, поэтому в сетку строк реестра не вмешивается.
- **Проверки «ничего лишнего не тронуто» нельзя делать через `git diff`**: каталог практики 5 целиком не отслеживается git, и `git diff` по его файлам всегда пуст — такая проверка молча проходит, ничего не проверив → сравнение идёт с базовой версией явно: `git show a80c913:practices/practice_04/project/<файл> | diff -u - <файл>`.
- **Счётчик как `role="status"` объявляется при каждой смене фильтра** и может быть болтливым для скринридера → текст короткий и фиксированного формата, одна фраза на событие.
- **Пустой результат — не ошибка ввода**, поэтому сообщение о нём не красится `--stamp`: по `docs/style-guide.md` этот цвет только для ошибок ввода. Используется `--ink-2` как вторичный текст.
