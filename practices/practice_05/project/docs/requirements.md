# Требования: лендинг проката автомобилей AutoDrive

AutoDrive — вымышленный прокат автомобилей. Нужен одностраничный лендинг, где посетитель выбирает машину и сразу видит стоимость аренды.
Страница открывается как статика: `python3 -m http.server 8000` из корня проекта, адрес `http://localhost:8000/`.

## Фича A: лендинг

Файлы: `index.html`, `styles.css`, при необходимости `src/main.js`.

Секции по порядку, у каждой свой `id` для навигации:

1. Шапка: логотип-текст AutoDrive и меню-якоря на все секции ниже.
2. `#hero`: заголовок `h1` (единственный на странице), подзаголовок, кнопка «Выбрать автомобиль» ведёт на `#fleet`.
3. `#fleet`: автопарк — не меньше 6 карточек. В карточке: модель (вымышленная), класс (`economy`, `comfort`, `business`, `suv`), коробка, число мест, цена за сутки, кнопка «Рассчитать». Каждая карточка имеет атрибут `data-car-id`.
4. `#benefits`: 3–4 преимущества.
5. `#how`: как арендовать — 3 шага.
6. `#faq`: 4 вопроса через `details/summary`.
7. `#contacts`: заглушки контактов из `AGENTS.md`, без реальных адресов.

Данные автопарка лежат в `src/cars.js` (экспорт массива `cars`: `id`, `model`, `class`, `gearbox`, `seats`, `pricePerDay`), разметка карточек строится из этого массива.

Критерии приёмки A:
- Все ссылки меню ведут на существующие `id`; `h1` ровно один.
- У каждого `img` и `svg` с смыслом есть `alt` или `aria-label`.
- Нет внешних ресурсов (`http://`, `https://` в `src`/`href`, кроме `#` и относительных путей).
- Вёрстка не ломается на ширине 360 px и 1280 px (нет горизонтального скролла).
- `sh scripts/check.sh` проходит; тесты проверяют данные `cars` и структуру `index.html`.

## Фича B: калькулятор стоимости

Секция `#calculator` между `#fleet` и `#benefits`. Логика — чистая функция в `src/calc.js`:

```js
calculateRental({ carId, days, extras }) // extras: массив из 'child-seat', 'extra-driver', 'full-insurance'
```

Правила расчёта:
- База: `pricePerDay × days`.
- Скидка за срок от базы: 7–13 суток — 10 %, от 14 суток — 15 %.
- Опции за сутки: детское кресло 300 ₽, второй водитель 500 ₽.
- Полная страховка: 15 % от базы после скидки.
- Залог (возвращается, в итог не входит): economy 10 000 ₽, comfort 15 000 ₽, business 30 000 ₽, suv 25 000 ₽.
- Ответ: `{ base, discount, extrasTotal, insurance, total, deposit }`, все суммы округлены до рубля.

Ошибочный ввод — функция бросает `RangeError` с понятным текстом, на странице показывается это сообщение, итог не выводится:
- `days` не целое число или вне 1–30;
- неизвестный `carId` или неизвестная опция.

Интерфейс: выбор автомобиля, число суток, чекбоксы опций, итог с расшифровкой (форматирование через `formatPrice`). Кнопка «Рассчитать» в карточке автопарка выбирает эту машину в калькуляторе и прокручивает к нему.

Критерии приёмки B:
- Тесты на `calculateRental`: обычный расчёт, обе границы скидки (6/7, 13/14 суток), опции, страховка, все ошибочные входы.
- Сценарии A сохраняются: тесты A проходят, меню содержит ссылку на `#calculator`.

## Фича C: фильтр автопарка

Отбор машин в `#fleet` по классу и коробке передач. Логика — чистые функции в `src/filter.js`:

```js
filterCars(cars, { carClass, gearbox }) // 'any' или отсутствие значения — без ограничения
```

Правила отбора:
- Условия по классу и по коробке сочетаются по И.
- Значение `'any'` (и отсутствующее значение) не ограничивает отбор по этому признаку.
- Порядок машин сохраняется тот же, что в массиве `cars`.
- Неизвестное значение класса или коробки — `RangeError` с понятным текстом, называющим полученное значение и допустимые.

Интерфейс: два `<select>` в `#fleet` — класс и коробка, оба по умолчанию в значении «любой», отбор применяется сразу по событию `change`, кнопки «Применить» нет. Рядом счётчик «Показано N из M» в своей области с `role="status"`; `#fleet-status` остаётся за сообщением о выбранной машине. Пустой результат показывает строку «Под эти условия машин нет — выберите «Любой класс» или «Любая коробка»», шапка реестра при этом скрыта. Разметку опций, текст счётчика и текст пустого результата дают чистые функции `filterOptionsHtml`, `countLabel` и константа `EMPTY_MESSAGE` из того же `src/filter.js`.

Критерии приёмки C:
- Тесты на `filterCars`: отбор по классу, отбор по коробке, сочетание по И, оба «любой» отдают весь автопарк в прежнем порядке, пустой результат, неизвестные значения класса и коробки.
- Тесты на `filterOptionsHtml`, `countLabel` и `EMPTY_MESSAGE`.
- Критерий A «не меньше 6 карточек» относится к состоянию фильтра по умолчанию: при активном фильтре показанных карточек закономерно меньше шести, и это не нарушение критерия A.
- Сценарии A и B сохраняются: кнопка «Рассчитать» и отметка выбранной машины работают после смены фильтра, список машин в `#calculator` остаётся полным.
- Если выбранная машина отфильтрована, отметки в реестре нет, `#fleet-status` не меняется, машина остаётся выбранной в калькуляторе.

Вне объёма фичи C: фильтры по цене и числу мест, текстовый поиск по модели, сортировка, кнопка сброса фильтра, хранение состояния в URL или `localStorage`, фильтрация списка машин в калькуляторе.

## Фича D: заявка на бронирование

Посчитав стоимость в калькуляторе, посетитель отправляет заявку на выбранную машину: имя, телефон, дата начала аренды. Срок и опции берутся из расчёта. Сервер проверяет заявку, сам пересчитывает цену и отвечает номером заявки. Машина не может быть забронирована дважды на пересекающиеся даты. Хранение — в памяти процесса, без БД, без авторизации, оплаты и e-mail/SMS.

**Источник имён — `specs/contracts/booking-contract.md`.** Имена полей, коды ошибок, состояния формы, видимые тексты, пути и коды ответов берутся только оттуда; ни UI, ни логика не вводят своих. Эта секция описывает продукт и критерии приёмки, но не дублирует контракт.

Страницу и API отдаёт один процесс Node 24 на встроенных модулях, порт 8000: `npm start` (вместо прежнего `python3 -m http.server 8000`). UI и API на одном источнике, CORS не нужен.

Ручки (контракт §5):

```http
POST /api/bookings        → 201 | 200 | 400 | 409 | 413 | 415 | 500
GET  /api/bookings/{id}   → 200 | 404
```

Логика — чистые функции:

```js
validateBooking(payload, today)   // src/booking.js — один предикат для UI и сервера
overlaps(a, b)                    // src/booking.js — пересечение полуоткрытых интервалов
```

Правила:
- Поля заявки и правила каждого поля — контракт §4 и §6; горизонт бронирования 365 суток, «сегодня» и календарная арифметика — UTC.
- Цена считается только существующим `calculateRental` из `src/calc.js`; правила расчёта не дублируются, сам модуль не меняется.
- Занятый период — полуоткрытый интервал `[startDate, startDate + days)`: день возврата свободен, встык бронировать можно (контракт §8).
- Повторная полностью идентичная заявка возвращает существующую бронь с кодом `200`, а не отказ «машина занята» (контракт §9).
- Проверка полей идёт до проверки занятости; отклонённая заявка не меняет хранилище и не расходует номер.
- Номер заявки — `AD-0001`, `AD-0002`, …; перезапуск процесса обнуляет хранилище и нумерацию.

Критерии приёмки D:
- Корректная заявка на свободную машину получает номер, а цена в ответе совпадает с итогом калькулятора для тех же машины, срока и опций.
- Пересечение дат на одной машине отклоняется с `409` и названным занятым интервалом; встык и другая машина проходят.
- Неверные поля отклоняются с `400` и разбором по полям в порядке `carId`, `days`, `extras`, `name`, `phone`, `startDate`; достижимы все 16 кодов каталога контракта §7.
- Повторная отправка той же заявки не создаёт вторую бронь.
- Любой запрос — корректный, ошибочный или бессмысленный — получает ответ в единой форме JSON; процесс не падает.
- Тесты на `validateBooking`, `overlaps`, хранилище и сквозные HTTP-тесты (поднимают сервер на свободном порту) проходят; сценарии A, B и C сохраняются.
