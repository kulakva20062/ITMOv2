# Master Prompt P2-FIX — закрытие ревью PR #3 (Практика 2)

Техника: **R.C.T.F. (Role — Context — Task — Format) с обязательным
завершающим проходом Chain of Verification.**

Почему именно эта пара, а не другая. Задача не исследовательская:
альтернативы уже выбраны, формулировки-замены уже выведены в шести
`experiment.md` и лежат в них дословно. Искать здесь нечего — нужно
перенести готовое в файлы и не соврать в описании. Поэтому:

- R.C.T.F. задаёт рамку исполнителю, который не может переспросить:
  адресат, закрытый набор источников, точный перечень правок, формат
  вывода. Это снимает главный риск — импровизацию и новые сущности.
- Chain of Verification закрывает ровно тот дефект, который нашёл
  ревьюер: эксперимент утверждал изменение, которого в файле нет.
  Единственная защита от повторения — проверка каждого утверждения
  о выполненной правке против фактического содержимого файла на диске
  после правки. Само-проверка по цитате, а не по памяти о своих
  действиях.

Tree of Thoughts, Few-shot, RAG и ReAct здесь не подходят и применяться
не должны: ToT перебирает альтернативы — они уже выбраны; Few-shot
задаёт образец однотипного элемента — образец уже сформулирован в
`few_shot/experiment.md`; RAG проверяет границу набора источников —
граница не оспаривается; ReAct нужен для обхода с неизвестным заранее
маршрутом — здесь маршрут известен поимённо, все пять адресов названы.
