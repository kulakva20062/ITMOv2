# Требования: фичи A и B для `experiment.py`

Это контракт Практики 4. Код и тесты меняются под него, а не наоборот.
Менять этот файл можно только по поручению студента.

## Общие правила

- Только стандартная библиотека Python 3.10+.
- Успешный запуск ведёт себя как раньше: тот же запрос к
  `http://127.0.0.1:11434/api/chat`, тот же формат JSON-записи
  (`request`, `response`, `wall_seconds`, `load_seconds`, `total_seconds`,
  `decode_tokens_per_second`), тот же вывод в stdout.
- Любая ошибка: одна понятная строка в stderr, без traceback.
- При любой ошибке файл результата не создаётся.

Коды выхода:

| Код | Значение |
|---|---|
| 0 | успешный запуск |
| 2 | некорректный запуск (аргументы, промпт); HTTP-запрос не делался |
| 3 | ошибка зависимости (Ollama) |

## Фича A. Проверка входа до вызова LLM

`experiment.py` проверяет запуск до любого HTTP-запроса и отклоняет его, если:

| Ситуация | Пример сообщения в stderr |
|---|---|
| файл `--output` уже существует | `ошибка: файл результата уже существует: out.json` |
| `--temperature` вне [0, 2] | `ошибка: --temperature должна быть в диапазоне [0, 2], получено 2.5` |
| пустое `--model` (в том числе из пробелов) | `ошибка: --model не может быть пустым` |
| итоговый промпт длиннее `MAX_PROMPT_CHARS` | `ошибка: промпт 9000 символов, максимум 7000` |

Во всех случаях: код выхода 2, одна строка в stderr, `urlopen` не вызывается,
файл результата не создаётся. Ошибки argparse (нет `--mode`, не число в
`--temperature`) остаются как есть: argparse и так выходит с кодом 2 до запроса.

### Допущение: `MAX_PROMPT_CHARS = 7000`

«Итоговый промпт» — сумма длин (в символах) содержимого всех сообщений:
`system.txt` (в режиме `system`) + `demo/README.md` + вопрос.

Обоснование:

- окно контекста `num_ctx = 4096` токенов, из них `num_predict = 512`
  нужно оставить под ответ — на вход остаётся 3584 токена;
- около 84 токенов уходит на шаблон чата (служебные токены ролей), берём
  с запасом 3500 токенов на текст;
- текст в основном русский; для Qwen это примерно 2–3 символа на токен.
  Берём нижнюю, осторожную оценку 2 символа на токен: 3500 × 2 = 7000 символов.

Текущий промпт — 554 символа, то есть лимит не мешает штатному сценарию.
Это оценка, а не подсчёт токенизатором: при смене модели или языка её
нужно пересмотреть.

## Фича B. Ошибка зависимости (Ollama)

- Новый аргумент `--timeout` в секундах, `float`, по умолчанию 300.
  Значение должно быть конечным числом больше 0 (`nan` и `inf` отклоняются).
  Неверное значение отклоняется по правилам A
  (код 2, одна строка, без запроса): `ошибка: --timeout должен быть больше 0, получено 0`.
- Значение `--timeout` передаётся в `urlopen(..., timeout=...)`.
- Ошибки Ollama дают код выхода 3 и одну строку в stderr без traceback:

| Ситуация | Сообщение |
|---|---|
| соединение отклонено (`URLError` с `ConnectionRefusedError`) | `Ollama недоступна на 127.0.0.1:11434 — запустите \`ollama serve\`` |
| таймаут (`TimeoutError` / `socket.timeout`, в том числе внутри `URLError`) | `Ollama не ответила за N с` |
| HTTP 404 или тело ошибки вида `{"error": "model 'X' not found"}` | `модель X не найдена — \`ollama pull X\`` |
| прочие HTTP-ошибки | `Ollama вернула HTTP <код>: <текст error из тела, если есть>` |
| ответ не является валидным JSON | `Ollama вернула невалидный JSON (HTTP 200)` |
| прочие сетевые ошибки (`URLError`) | `ошибка соединения с Ollama: <причина>` |

- Файл результата при ошибке не создаётся.
- Все сценарии A сохраняются и проверяются до запроса.

Формат ошибки `/api/chat` для отсутствующей модели (сверить через Context7):
HTTP 404 и JSON-тело `{"error": "model 'X' not found"}`.
